## 第一章 项目概述

### 1.1 项目背景

HealthApp 是一套面向中小型医院/诊所的智慧医疗预约系统，覆盖**患者端、医生端、管理端**三端业务，并集成**AI智能医疗助手**，为医生提供临床决策支持，为患者提供健康咨询服务。

本项目从一个Spring Boot小Demo进化为企业级架构，引入微服务治理、消息队列、多级缓存、分布式锁、AI Agent等企业级技术栈。

### 1.2 核心业务模块

| 模块 | 说明 | 面向角色 |
|------|------|----------|
| 预约挂号 | 科室选择→医生选择→时间选择→确认预约全流程 | 患者 |
| 缴费管理 | 医生开单→收费员缴费→退款→日终结算 | 患者/医生/收费员 |
| 电子病历 | 主诉、现病史、诊断、治疗方案、医嘱 | 医生 |
| 处方管理 | 开处方、审核、发药、退药 | 医生/药师 |
| 消息通知 | 预约成功/取消、缴费通知、就诊提醒等 | 患者/医生 |
| 医生请假 | 常规请假、紧急请假、自动取消关联预约 | 医生 |
| AI智能助手 | RAG知识检索、工具调用、多轮对话、流式输出 | 医生/患者 |
| 数据看板 | 预约趋势、营收统计、科室排行、医生工作量 | 管理员 |

### 1.3 项目亮点（面试加分项）

1. **微服务架构准备**：Spring Cloud Alibaba（Nacos + Sentinel + OpenFeign）
2. **AI Agent**：LangChain + RAG + Function Calling + ReAct推理
3. **多级缓存**：Caffeine本地缓存 + Redis分布式缓存
4. **消息队列**：RabbitMQ异步解耦 + 死信队列 + 手动ACK
5. **分布式锁**：Redisson可重入锁 + 延迟队列
6. **企业级规范**：统一响应、统一异常、参数校验、操作日志、接口幂等、限流
7. **三端分离**：患者端/医生端/管理端独立布局和权限
8. **数据可视化**：ECharts多维图表看板

### 3.3 调用链路示例（患者预约）

```

  → RateLimitAspect（限流检查）
  → IdempotentAspect（幂等检查）
  → AppointmentController.submit()
  → AppointmentServiceImpl.submit()
    → Redisson分布式锁（防并发超卖）
    → 校验：日期/医生状态/请假/重复预约/号源数量
    → 写入appointment表
    → 更新patient_limit表
    → MessageProducer发送RabbitMQ消息（异步通知）
    → 返回预约成功
  → OperationLogAspect（记录操作日志）
  → 全局异常处理（如有异常）
```

### 4.4 认证授权机制

**JWT认证流程**

```
1. 用户登录 → 验证账号密码 → 生成JWT Token（含userId/username/userType）
2. 前端存储Token（localStorage）
3. 后续请求Header携带: Authorization: Bearer <token>
4. JwtAuthenticationFilter拦截 → 解析Token → 设置UserContext + SecurityContext
5. Controller通过UserContext.getUserId()获取当前用户
6. 请求结束 → ThreadLocal清理（防止内存泄漏）
```

**Token结构（Payload）**

```json
{
  "userId": 1,
  "username": "13800138000",
  "userType": 1,
  "iat": 1234567890,
  "exp": 1234567890
}
```

**用户类型**：1-患者，2-医生，3-管理员

### 4.5 分布式锁（Redisson）

**使用场景**

| 场景 | 锁Key | 锁类型 | 超时 |
|------|-------|--------|------|
| 预约提交 | appoint:lock:{doctorId}:{date}:{period} | 可重入锁 | 10s |
| 取消预约 | appoint:cancel:{id} | 可重入锁 | 5s |
| 订单支付 | order:lock:{orderNo} | 可重入锁 | 10s |

**预约防超卖核心代码逻辑**

```java
RLock lock = redissonClient.getLock(lockKey);
boolean locked = lock.tryLock(3, 10, TimeUnit.SECONDS);
if (!locked) return Result.fail("系统繁忙");
try {
    // 1. 二次校验号源数量
    // 2. 插入预约记录
    // 3. 更新限制计数
} finally {
    if (lock.isHeldByCurrentThread()) lock.unlock();
}
```

### 4.6 延迟队列（订单超时自动作废）

**两种实现方式**

1. **Redisson延迟队列**（原有实现）：RDelayedQueue
2. **RabbitMQ死信队列**（企业级方案）：TTL + DLX

**RabbitMQ死信方案流程**

```
创建订单 → 发送到order.timeout队列（设置TTL=24h）
  → 24小时后消息过期 → 进入死信交换机 → 死信队列
  → 消费者检查订单状态 → 若仍为待缴费 → 自动作废
```

### 4.8 消息队列设计

**交换机-队列拓扑**

```
healthapp.message.exchange (Topic)
  ├── message.patient.# → healthapp.message.patient 队列
  └── message.doctor.#  → healthapp.message.doctor 队列

healthapp.order.exchange (Topic)
  └── order.timeout → healthapp.order.timeout 队列

healthapp.ai.exchange (Topic)
  ├── ai.task   → healthapp.ai.task 队列
  └── ai.result → healthapp.ai.result 队列

healthapp.deadletter.exchange (Direct)
  └── deadletter → healthapp.deadletter.queue 队列（死信）
```

**消息可靠性保障**

1. **生产者确认**：publisher-confirm-type=correlated
2. **消息返回**：publisher-returns=true（路由失败回调）
3. **消费者手动ACK**：acknowledge-mode=manual
4. **消费失败重试**：最多3次，失败进入死信队列
5. **队列持久化**：durable=true

### 4.9 接口幂等性设计

**@Idempotent注解 + Redis SETNX**

```
请求到达 → IdempotentAspect拦截
  → 生成幂等Key（SpEL表达式解析参数）
  → Redis SETNX（key, 1, expire=60s）
  → 成功：执行业务逻辑
  → 失败：抛出"重复提交"异常
  → 业务异常：删除Key，允许重试
```

**应用场景**：预约提交、订单支付、退款申请

### 4.10 接口限流设计

**@RateLimit注解 + Redisson RateLimiter**

| 限流维度 | 说明 | 示例 |
|----------|------|------|
| IP限流 | 按客户端IP限流 | 登录接口防暴力破解 |
| 用户限流 | 按用户ID限流 | AI对话30次/分钟 |
| 全局限流 | 接口级别的全局限流 | 预约接口100次/分钟 |

**滑动窗口算法**：Redisson RRateLimiter基于令牌桶实现

### 4.11 操作日志

**@OperationLog注解 + AOP异步记录**

记录字段：用户ID、用户名、操作模块、操作描述、操作类型、请求方法、请求参数、返回结果、IP、URI、耗时、状态、错误信息

#### POST /api/v1/appointment/submit - 提交预约（核心接口）

**描述**：患者提交预约，包含完整的业务校验和并发控制

**安全机制**：分布式锁 + 幂等性 + 限流

**请求参数（Body）**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| deptId | Integer | 是 | 科室ID |
| doctorId | Integer | 是 | 医生ID |
| appointDate | String | 是 | 预约日期 |
| timePeriod | String | 是 | 上午/下午 |

**请求头**：patientId（从JWT解析）

**业务校验流程**

```
1. 获取分布式锁 appoint:lock:{doctorId}:{date}:{period}
2. 校验日期：不能预约过去日期，只能预约未来7天内
3. 校验当日截止时间：上午12点前，下午18点前
4. 校验医生存在且未停诊
5. 校验科室与医生匹配
6. 校验医生此时段未请假
7. 校验未重复预约同一时段
8. 校验当日预约次数≤1
9. 校验该时段号源未满（每医生每时段15人）
10. 校验当日取消次数≤3
11. 插入预约记录（queue_num=当前人数+1）
12. 更新patient_limit计数
13. 发送RabbitMQ消息（患者预约成功通知 + 医生新预约通知）
14. 释放锁
```

**响应数据**

```json
{
  "code": 200,
  "message": "预约成功",
  "data": {
    "queueNum": 3,
    "frontCount": 2,
    "appointment": { "id": 100, "status": 0, ... }
  }
}
```

**错误码**：30005日期不合法、30006医生不存在、30007医生请假、30008医生停诊、30003重复预约、30002号源已满、30004取消次数超限

### 6.3 缴费管理接口

#### POST /api/v1/pay/create - 医生开立缴费单

**描述**：医生为已签到患者开具缴费单，支持多条费用明细

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|

6. 保存缴费单 + 费用明细（批量插入）
7. 更新预约状态为"已开单待缴费"
8. 发送患者缴费通知
9. 投递延迟队列（超时自动作废）

#### POST /api/v1/pay/pay - 确认缴费

**描述**：收费员确认患者缴费

**安全机制**：分布式锁防并发重复支付

**请求参数**

| 参数 | 类型 | 必填 | 说明 |

**业务逻辑**：

4. 校验未过期
5. 获取分布式锁 order:lock:{orderNo}
6. 二次校验状态（Double Check）
7. 生成交易流水号 TXN + yyyyMMddHHmmss + 6位随机数
8. 更新订单状态为"已缴费"
9. 更新预约状态为"已缴费诊疗中"
10. 发送缴费成功消息
11. 移除延迟队列中的超时任务

### 6.6 AI Agent接口

#### POST /api/v1/agent/chat - 提交AI对话（异步）

**描述**：提交问题到AI Agent，立即返回taskId，前端轮询获取结果

**限流**：30次/分钟/用户

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| question | String | 是 | 用户问题 |
| session_id | String | 否 | 会话ID（多轮对话） |

**响应**：`{ task_id: "xxx", status: "processing" }`

**处理流程**：
1. 校验问题非空
2. 生成taskId
3. Redis设置任务状态为processing
4. 保存对话历史到Redis（List结构，24小时过期）
5. 发送RabbitMQ消息到ai.task队列
6. Python Agent消费消息，调用LLM+工具+RAG
7. 结果写入Redis（ai:result:{taskId}）

### 7.2 系统提示词设计

```
你是一名专业的医疗智能助手，名为"医智助手"。

能力：
1. 解答医学问题（疾病知识、用药指导、检查解读）
2. 调用工具查询患者信息、预约、病历、药品
3. 检索医学知识库，提供权威指南

原则：
1. 专业严谨，基于循证医学，不编造
2. 安全第一，提醒"仅供参考，遵医嘱"
3. 工具优先，需要数据时必须调用工具
4. 知识检索，专业问题优先RAG
5. 表达清晰，通俗易懂

安全护栏：
- 不提供具体处方剂量（除工具计算外）
- 不替代医生诊断
- 急症立即建议120/急诊
```

### 7.3 ReAct推理循环

```
迭代1:
  LLM(问题+上下文+工具定义) → 决定调用 query_patient_info
  执行工具 → 返回患者信息
  ↓
迭代2:
  LLM(问题+上下文+患者信息) → 决定调用 medical_knowledge_search
  执行工具 → 返回高血压诊疗指南
  ↓
迭代3:
  LLM(问题+上下文+患者+指南) → 无需工具，生成最终答案
  ↓
返回答案（含免责声明）
```

### 7.4 工具详细说明

#### 工具1：query_patient_info - 查询患者信息

**功能**：根据患者ID查询基本信息（姓名、性别、年龄、手机号）

**参数**：patient_id (integer, 必填)

**使用场景**：医生询问"患者张三的基本情况"

---

#### 工具2：query_appointments - 查询预约记录

**功能**：查询患者的预约记录，支持按状态过滤

**参数**：patient_id (必填), status (可选)

**使用场景**："查询我的预约"、"患者最近有哪些预约"

---

#### 工具3：query_medical_records - 查询电子病历

**功能**：查询患者历史病历，包括诊断、治疗方案

**参数**：patient_id (必填), limit (可选，默认5)

**使用场景**："患者之前有什么病史"、"查看病历"

---

#### 工具4：query_drug_info - 查询药品信息

**功能**：模糊查询药品，返回用法用量、禁忌、不良反应、价格

**参数**：drug_name (string, 必填)

**使用场景**："阿莫西林怎么用"、"布洛芬有什么禁忌"

---

#### 工具5：query_department_doctors - 查询科室医生

**功能**：查询指定科室的医生列表和出诊状态

**参数**：dept_id 或 dept_name

---

#### 工具6：medical_knowledge_search - 医学知识检索（RAG）

**功能**：从ChromaDB向量数据库检索权威医学知识

**参数**：query (string, 必填), top_k (可选，默认3)

**使用场景**：所有专业医学问题优先调用

---

#### 工具7：calculate_drug_dosage - 计算用药剂量

**功能**：根据患者体重计算儿童用药剂量

**参数**：drug_name, weight_kg, dose_per_kg, frequency

**输出**：单次剂量、每日剂量、警告提示

### 7.5 RAG检索流程

```
用户问题
  ↓
Query改写（可选）
  ↓
BGE嵌入模型 → 问题向量
  ↓
ChromaDB相似度检索（cosine）
  ↓
Top-K结果（默认5条）
  ↓
格式化：[参考1 | 来源:xxx | 相关度:0.85] 内容...
  ↓
注入System Prompt
  ↓
LLM生成答案（基于检索结果，不编造）
```

## 第九章 安全设计

### 9.1 认证授权

| 机制 | 说明 |
|------|------|
| JWT Token | 无状态认证，含用户ID/角色，7天过期 |
| BCrypt | 密码哈希存储，不可逆 |
| Spring Security | 权限框架，角色控制 |
| 接口权限 | 患者/医生/管理员三端隔离 |

### 9.2 数据安全

| 措施 | 说明 |
|------|------|
| 逻辑删除 | 所有业务表deleted字段，不物理删除 |
| 敏感字段 | 身份证号等可加密存储 |
| SQL注入防护 | MyBatis参数化查询，禁止字符串拼接 |
| XSS防护 | 前端输出转义 + 后端输入校验 |
| CSRF防护 | JWT机制天然防护 |

### 9.3 接口安全

| 措施 | 实现 |
|------|------|
| 限流 | @RateLimit + Redisson RateLimiter |
| 幂等 | @Idempotent + Redis SETNX |
| 操作日志 | @OperationLog + AOP异步记录 |
| 参数校验 | Jakarta Validation + 全局异常处理 |
| 统一响应 | 不暴露堆栈信息 |

### 9.4 AI安全

| 措施 | 说明 |
|------|------|
| 医疗免责声明 | 所有AI回答末尾添加"仅供参考，遵医嘱" |
| 内容安全 | 不提供具体处方剂量（除工具计算） |
| 急症识别 | 胸痛/呼吸困难等立即建议120 |
| 调用限流 | 30次/分钟/用户 |
| 对话审计 | ai_conversation表记录所有对话 |

## 第十一章 部署架构

### 11.1 Docker Compose 部署

```yaml
services:
  mysql:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: 123456

    image: redis:7-alpine
    ports: ["6379:6379"]

  rabbitmq:

    image: nacos/nacos-server:v2.3.0
    ports: ["8848:8848"]

    build: ./HealthApp
    ports: ["8081:8081"]

  agent:
    build: ./python-agent
    ports: ["8000:8000"]

    ports: ["80:80"]

```

cd healthapp-web
npm install
npm run dev
# 访问 http://localhost:3000
