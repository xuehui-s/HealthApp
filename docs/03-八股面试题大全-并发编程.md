# 八股面试题大全 - 并发编程篇

> 覆盖：线程、锁、线程池、并发容器、JUC、AQS

---

## 一、线程基础

### 1. 线程的生命周期？

**答案**：

```
新建(NEW) → 就绪(RUNNABLE) → 运行(RUNNING) → 阻塞(BLOCKED/WAITING/TIMED_WAITING) → 终止(TERMINATED)
```

- NEW：创建Thread对象，未调用start()
- RUNNABLE：调用start()，等待CPU调度
- RUNNING：获得CPU时间片，执行中
- BLOCKED：等待synchronized锁
- WAITING：调用wait()/join()/LockSupport.park()，无限等待
- TIMED_WAITING：sleep(time)/wait(time)/join(time)，限时等待
- TERMINATED：run()执行完毕或异常退出

---

### 2. 线程的创建方式？

**答案**：
1. 继承Thread类，重写run()
2. 实现Runnable接口，重写run()，作为Thread构造参数
3. 实现Callable接口，重写call()，用FutureTask包装，可获取返回值和异常
4. 线程池创建（生产环境推荐）

**Runnable vs Callable**：Runnable无返回值，Callable有返回值且可抛异常。

---

### 3. sleep()和wait()的区别？

**答案**：

| 特性 | sleep() | wait() |
|------|---------|--------|
| 所属类 | Thread | Object |
| 释放锁 | 不释放 | 释放 |
| 唤醒 | 时间到自动醒 / interrupt | notify()/notifyAll() / 时间到 |
| 使用位置 | 任意 | synchronized块中 |
| 用途 | 暂停执行 | 线程间通信 |

---

### 4. 为什么wait()/notify()定义在Object类中？

**答案**：因为每个对象都可以作为锁（monitor），wait/notify是锁级别的操作，所以定义在所有类的父类Object中。而sleep是线程级别的操作，定义在Thread中。

---

### 5. 线程池的核心参数？

**答案**：ThreadPoolExecutor七大核心参数：

1. **corePoolSize**：核心线程数，即使空闲也保留
2. **maximumPoolSize**：最大线程数
3. **keepAliveTime**：非核心线程空闲存活时间
4. **unit**：时间单位
5. **workQueue**：任务队列（BlockingQueue）
6. **threadFactory**：线程工厂，创建线程
7. **handler**：拒绝策略

**执行流程**：
```
任务提交 → 核心线程数未满？→ 创建核心线程执行
         → 核心线程满？→ 加入队列
         → 队列满？→ 创建非核心线程（直到maximumPoolSize）
         → 最大线程满？→ 执行拒绝策略
```

---

### 6. 四种拒绝策略？

**答案**：
1. **AbortPolicy**（默认）：抛出RejectedExecutionException
2. **CallerRunsPolicy**：由提交任务的线程执行（降级，不会丢失任务）
3. **DiscardPolicy**：直接丢弃任务，不抛异常
4. **DiscardOldestPolicy**：丢弃队列中最旧的任务，然后重试提交

---

### 7. 常见的阻塞队列？

**答案**：

| 队列 | 特点 |
|------|------|
| ArrayBlockingQueue | 有界数组，FIFO，需指定容量 |
| LinkedBlockingQueue | 链表，默认Integer.MAX_VALUE（有OOM风险） |
| SynchronousQueue | 不存储任务，直接交给线程（CachedThreadPool用） |
| PriorityBlockingQueue | 优先级队列，无界 |
| DelayQueue | 延迟队列，元素到期才能取出 |

---

### 8. Executors提供的线程池？为什么生产环境不推荐？

**答案**：
- newFixedThreadPool：固定线程数，LinkedBlockingQueue（无界队列，OOM风险）
- newCachedThreadPool：可缓存线程，SynchronousQueue，最大线程Integer.MAX_VALUE（OOM风险）
- newSingleThreadExecutor：单线程，LinkedBlockingQueue（无界队列）
- newScheduledThreadPool：定时任务线程池

**不推荐原因**：
1. 队列或最大线程数无界，可能OOM
2. 线程名默认，不利于排查
3. 无法自定义拒绝策略

**生产环境推荐**：手动new ThreadPoolExecutor，合理设置参数。

---

### 9. 线程池如何合理设置参数？

**答案**：
- **CPU密集型**：corePoolSize = CPU核数 + 1（如计算、加密）
- **IO密集型**：corePoolSize = CPU核数 * 2 或 CPU核数 / (1 - 阻塞系数)，阻塞系数约0.8~0.9（如数据库、网络请求）
- **混合型**：拆分为两个线程池分别处理

**实际公式**：线程数 = CPU核数 * (1 + 等待时间/计算时间)

---

### 10. 线程池的状态？

**答案**：
- RUNNING：接受新任务，处理队列任务
- SHUTDOWN：不接受新任务，处理队列任务（调用shutdown()）
- STOP：不接受新任务，不处理队列，中断运行中任务（shutdownNow()）
- TIDYING：所有任务终止，workerCount=0
- TERMINATED：terminated()方法执行完毕

## 二、锁机制

### 11. synchronized的底层原理？

**答案**：synchronized基于对象监视器（monitor）实现。

**对象头Mark Word**存储锁信息：
- 无锁：01
- 偏向锁：01（带线程ID）
- 轻量级锁：00
- 重量级锁：10

**锁升级过程**（JDK1.6后）：
1. **偏向锁**：第一个线程获取锁时，Mark Word记录线程ID，该线程再次进入无需CAS
2. **轻量级锁**：多线程交替执行时，CAS自旋获取锁，不阻塞
3. **重量级锁**：多线程同时竞争，自旋失败后升级，依赖OS mutex，线程阻塞

**synchronized锁的是对象**，不是代码。静态方法锁的是类对象（Class对象）。

---

### 12. synchronized和ReentrantLock的区别？

**答案**：

| 特性 | synchronized | ReentrantLock |
|------|-------------|---------------|
| 实现 | JVM层面，monitor | JDK层面，AQS |
| 释放 | 自动释放 | 必须手动unlock()（finally中） |
| 公平锁 | 非公平 | 可配置公平/非公平 |
| 可中断 | 不可 | lockInterruptibly()可中断 |
| 超时获取 | 不支持 | tryLock(timeout) |
| 条件变量 | 单一 | 可绑定多个Condition |
| 性能 | 优化后差不多 | 高竞争下更灵活 |

---

### 13. 什么是AQS？

**答案**：AbstractQueuedSynchronizer，抽象队列同步器，是JUC锁的基础框架。

**核心思想**：
- 用一个volatile int state表示同步状态
- 用CLH队列（双向链表）存放等待线程
- 线程获取锁失败时，封装为Node加入队列尾部，自旋+阻塞等待
- 锁释放时，唤醒队列头节点的后继线程

**AQS两种模式**：
- 独占模式（Exclusive）：ReentrantLock
- 共享模式（Share）：Semaphore、CountDownLatch、ReadWriteLock读锁

**核心方法**：
- tryAcquire/tryRelease：独占模式获取/释放
- tryAcquireShared/tryReleaseShared：共享模式获取/释放
- isHeldExclusively：是否独占

---

### 14. ReentrantLock的公平锁和非公平锁？

**答案**：
- **非公平锁**（默认）：新线程可以直接CAS尝试获取锁，失败才排队。吞吐量高，但可能线程饥饿。
- **公平锁**：新线程必须排队，按FIFO获取锁。无饥饿，但吞吐量低（上下文切换多）。

**非公平锁为什么快**：减少了线程挂起和唤醒的开销，新线程可能直接获取锁。

---

### 15. 什么是可重入锁？

**答案**：可重入锁指同一个线程可以多次获取同一把锁而不会死锁。

**实现原理**：
- synchronized：monitor的_owner字段记录持有线程，recursions记录重入次数
- ReentrantLock：AQS的state记录重入次数，获取锁时判断是否是当前线程，是则state+1

**释放时**：每次unlock() state-1，state=0时真正释放锁。

---

### 16. 死锁的四个必要条件？如何避免？

**答案**：

**四个必要条件**：
1. 互斥：资源同一时间只能被一个线程持有
2. 占有且等待：持有资源的同时等待其他资源
3. 不可剥夺：资源不能被强行剥夺
4. 循环等待：线程间形成循环等待链

**避免方法**：
1. 破坏循环等待：统一加锁顺序（如按ID大小顺序加锁）
2. 破坏占有且等待：一次性申请所有资源
3. 破坏不可剥夺：ReentrantLock的tryLock超时机制
4. 使用定时锁，超时自动放弃

---

### 17. volatile的作用和原理？

**答案**：volatile有两个作用：
1. **可见性**：一个线程修改volatile变量，其他线程立即可见
2. **有序性**：禁止指令重排序（内存屏障）

**原理**：
- 写volatile变量时，加入StoreStore屏障 + 写操作 + StoreLoad屏障，强制刷新到主内存
- 读volatile变量时，加入LoadLoad屏障 + 读操作 + LoadStore屏障，强制从主内存读取

**volatile不能保证原子性**：i++不是原子操作（读-改-写三步）。

**使用场景**：状态标志位（如boolean running）、双重检查锁单例中的instance。

---

### 18. CAS的原理？ABA问题？

**答案**：CAS（Compare And Swap）是一种无锁原子操作。

**操作**：比较内存值V与预期值A，相等则更新为新值B，否则不更新。整个操作原子。

**Java实现**：Unsafe类的compareAndSwapXXX方法，底层CPU指令cmpxchg。

**ABA问题**：值从A变成B又变回A，CAS认为没变，但实际被修改过。

**解决**：
1. 版本号：AtomicStampedReference（带版本号的引用）
2. 时间戳：AtomicMarkableReference（布尔标记）

---

### 19. ThreadLocal的原理和内存泄漏？

**答案**：

**原理**：每个Thread对象有一个ThreadLocalMap，key是ThreadLocal对象（弱引用），value是线程私有值。

```
Thread → ThreadLocalMap → Entry(WeakReference<ThreadLocal>, value)
```

**内存泄漏**：
- ThreadLocal是弱引用，GC时key会被回收，但value是强引用不会被回收
- 如果线程长期存活（如线程池），value一直无法回收 → 内存泄漏

**解决**：使用完ThreadLocal后必须调用remove()方法。

**应用场景**：用户上下文（UserContext）、数据库连接、SimpleDateFormat线程安全、事务管理。

## 三、并发容器和工具

### 20. ConcurrentHashMap的size()如何计算？

**答案**：JDK1.8中：
1. 先尝试无锁计算baseCount + 各CounterCell的值
2. 如果计算过程中发生变化（contended），则锁住所有桶重新计算
3. CounterCell是一种分段计数机制，避免size()时的竞争

---

### 21. CountDownLatch和CyclicBarrier的区别？

**答案**：

| 特性 | CountDownLatch | CyclicBarrier |
|------|---------------|---------------|
| 作用 | 一个/多个线程等待其他线程完成 | 多个线程互相等待，到达屏障点 |
| 计数 | 递减，不可重置 | 递增，可重置复用 |
| 回调 | 无 | 可指定Runnable回调 |
| 场景 | 主线程等子线程完成 | 多线程计算后合并结果 |

---

### 22. Semaphore的作用？

**答案**：信号量，控制同时访问资源的线程数量。

- acquire()：获取许可，没有则阻塞
- release()：释放许可

**应用场景**：限流（如本项目的接口限流）、资源池控制（如数据库连接池）。

---

### 23. 什么是伪共享？如何解决？

**答案**：CPU缓存以缓存行（64字节）为单位，多个变量在同一缓存行时，一个线程修改会导致其他线程的缓存行失效，即使变量互不相关。

**解决**：缓存行填充（@Contended注解或手动填充7个long变量），使变量独占一个缓存行。

---

### 24. 什么是线程安全？如何保证？

**答案**：线程安全指多线程环境下程序行为正确，结果符合预期。

**保证线程安全的方法**：
1. 无状态（不共享变量）
2. 不可变对象（final）
3. 加锁（synchronized/ReentrantLock）
4. 原子类（AtomicInteger/CAS）
5. 线程封闭（ThreadLocal/局部变量）
6. 并发容器（ConcurrentHashMap）

---

### 25. 什么是happens-before原则？

**答案**：JMM定义的规则，保证一个操作的内存写对另一个操作可见。

**主要规则**：
1. 程序顺序规则：单线程内前面操作happens-before后面操作
2. 监视器锁规则：unlock happens-before 后续的lock
3. volatile规则：volatile写 happens-before 后续的volatile读
4. 传递性：A happens-before B，B happens-before C → A happens-before C
5. start规则：Thread.start() happens-before 线程内所有操作
6. join规则：线程内所有操作 happens-before Thread.join()返回
